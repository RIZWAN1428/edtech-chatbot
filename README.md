# EduSpark Support Chatbot

A multi-turn, context-aware customer support chatbot for an EdTech platform. It answers
questions using retrieval over a FAQ dataset (semantic search with a keyword-search
fallback), detects user frustration and out-of-scope queries, escalates to a human agent
when needed, and logs conversations with feedback.

## Features

- Multi-turn conversations with per-session context retention
- Answers grounded in a 40-item FAQ dataset (`data/faqs_cleaned.json`) using
  sentence-transformers + FAISS for semantic search, with an automatic keyword-search
  fallback if the embedding model isn't available
- Sentiment and frustration detection, with automatic escalation to a human agent
- Out-of-scope detection
- Session management for multiple users
- SQLite logging of every message with timestamps
- Thumbs up/down feedback, with disliked responses stored separately for review
- Mock customer profile lookup for personalized greetings
- Simple HTML/JS chat frontend
- Automated test suite (pytest)

## Dependencies

All listed in `requirements.txt`:

- fastapi, uvicorn — backend API server
- sentence-transformers, faiss-cpu, numpy — embeddings and vector search
- nltk — sentiment analysis (VADER)
- pydantic — request/response validation
- python-multipart

Dev/test only (not in requirements.txt, install separately if running tests):
- pytest, httpx

## Environment variables / configuration

No API keys or environment variables are required. Everything runs locally with free,
open-source models.

The only configurable value is the frontend's API base URL, in `frontend/config.js`:

```js
const API_BASE_URL = "http://127.0.0.1:8000";
```

Update this if you run the backend on a different host or port.

## Setup and running

Requires Python 3.8+.

```bash
# 1. Clone the repo
git clone <repo-url>
cd edtech-chatbot

# 2. (Recommended) create a virtual environment
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

# 3. Install dependencies
pip install -r requirements.txt

# 4. Start the backend
uvicorn app.main:app --reload
```

On first run, `sentence-transformers` downloads the `all-MiniLM-L6-v2` embedding model
(~80MB) from Hugging Face — this needs internet access once, then it's cached locally.
If the download fails (no internet, firewall, etc.), the app automatically falls back to
keyword-based search and keeps working.

The API is now running at `http://127.0.0.1:8000`. Interactive API docs are available at
`http://127.0.0.1:8000/docs`.

In a separate terminal, serve the frontend:

```bash
cd frontend
python3 -m http.server 8080
```

Open `http://127.0.0.1:8080` in a browser to use the chat interface.

### Running tests

```bash
pip install pytest httpx
pytest tests/ -v
```

## Design notes

Responses are retrieved verbatim from the FAQ dataset rather than generated by an LLM.
The embedding model (`all-MiniLM-L6-v2`) is used only to find the closest-matching FAQ by
meaning, not to write text — this keeps every answer grounded and avoids hallucination,
since the bot can never say anything that isn't one of the vetted FAQ entries.

Not implemented: authentication/login (session IDs provide basic multi-user isolation but
there's no user accounts system), and deployment as a Telegram/Slack/WhatsApp bot.
